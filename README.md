# 四象限分類ツール

任意の2軸を定義し、項目を `-1.0`〜`+1.0` の座標で登録・可視化するローカルWebアプリです。カラオケ、仕事、技術、ゲーム、アイデアなど用途を限定しません。

## 起動方法

- Python 3.10以上（外部Pythonパッケージ不要）
- Windowsでは、リポジトリのルートで `python server.py` を実行します。
- ターミナルに表示される `http://127.0.0.1:8765/` をブラウザーで開きます（既定では自動的に開きます）。
- 停止するにはターミナルで `Ctrl+C` を押します。
- ポートを変える場合は `python server.py --port 9000`、ブラウザーを自動起動しない場合は `python server.py --no-browser` を指定します。

Pythonサーバーは画面ファイルを配信するだけで、ユーザーデータや画像は受信・保存しません。サーバーは既定で `127.0.0.1` のみで待ち受けます。

## 基本操作

1. **設定**タブで設定ID・設定名・X/Y軸のポジティブ/ネガティブ側の名称を登録します。
2. **データ**タブでデータセットを作成し、使用する設定を選んで保存します。
3. 「項目を追加」から項目名、表示名、画像、X/Y評価、note、tagsを入力します。評価はスライダー・数値入力・小型マップのクリックで指定でき、それぞれ同期します。
4. **マップ**タブでデータセットを選ぶと、軸ラベル付きのマップが表示されます。タグで絞り込み、マップ上または項目一覧から項目を選ぶと詳細を確認できます。
5. **設定**タブの「JSONを書き出す」でバックアップを作り、「JSONを読み込む」でこのブラウザーや別ブラウザーへ移行できます。

データセット情報の変更は「データセットを保存」で保存します。項目の追加・編集・削除は操作ごとに保存されます。設定/データセットIDは作成後に変更できません。評価値0は中立です。

## 保存方式とプライバシー

設定・データセットはブラウザーのIndexedDB、画像はIndexedDBのBlobとして保存します。保存領域はブラウザーのオリジンとブラウザープロファイルごとに独立し、サーバー上の共通ユーザーデータファイルには書き込みません。画面再読み込み後も同じブラウザープロファイルでデータを利用できます。ブラウザーのサイトデータを消去すると保存データも消去されるため、定期的なJSON Exportを推奨します。

画像の最大サイズを10MBとしているため、一般的に容量の小さい `localStorage` ではなくIndexedDBを採用しました。IndexedDBは画像BlobをBase64化せずに保存でき、利用可能容量も大きいためです。保存処理は画面から分離したRepositoryとして実装し、将来別の保存先へ置き換えやすくしています。

## JSONバックアップ形式

Exportファイルは1つのJSONで、設定、データセット、画像を含みます。画像は手動移行できるようBase64 data URLとして格納します。

```json
{
  "format": "quadrant-mapper",
  "version": 1,
  "exported_at": "2026-10-02T00:00:00.000Z",
  "settings": [
    {
      "id": "karaoke",
      "name": "カラオケ曲分類",
      "axis_x": { "positive": "好き", "negative": "嫌い" },
      "axis_y": { "positive": "得意", "negative": "苦手" }
    }
  ],
  "datasets": [
    {
      "id": "karaoke_songs",
      "name": "カラオケ曲",
      "setting": "karaoke",
      "items": [
        {
          "id": "reset-song",
          "name": "Reset",
          "display_name": "Reset",
          "image": null,
          "x": 0.8,
          "y": 0.6,
          "note": "十八番候補",
          "tags": ["ゲーム"]
        }
      ]
    }
  ],
  "images": []
}
```

実際の画像がある場合は、`images` 配列に `{ "name": "画像ファイル名.png", "data": "data:image/png;base64,..." }` が入ります。`image` はその `name` を参照します。`setting` は設定IDを参照します。`display_name` が空の場合は `name` が表示されます。

ImportではJSON形式・バージョン、ID重複、必須値、設定参照、座標範囲、画像形式/サイズ/参照をすべて検証し、問題があれば変更を適用しません。既定の「統合」は異なるIDの既存データを残し、同じIDはImport側で上書きします。「すべて置き換える」は確認ダイアログの後、ブラウザー内データをバックアップ内容で置き換えます。

## 現在の制限

- 認証、サーバーDB、クラウド同期、複数端末の自動同期はありません。端末/ブラウザー間の移行はJSONバックアップを手動で行います。
- IndexedDBは同じブラウザープロファイル内で共有されます。共有端末でブラウザープロファイル自体を共有する場合、ユーザー間のアクセス分離にはなりません。
- マップ項目の自動配置調整は行いません。同じ座標付近の項目は少しずらして表示し、下部の項目一覧からも選択できます。
- 設定/データセット自体の削除機能はありません。画像は項目から外してもIndexedDB内に残り、バックアップにも含まれます。
